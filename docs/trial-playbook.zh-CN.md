# ALTER 两周免费试用 · 数据回收与判读方案

> 适用范围：50–100 名真实青少年，14 天免费试用，用试用数据决定是否放量。
> 前提：纯静态 PWA，无后端、无账号；所有数据只存在各自设备的 localStorage，由家长/组织者导出后汇总。
> 隐私边界：只回收统计类行为数据（事件名、本地日期、时间戳、场景/回合 id、判定结果、计数），**不收集对话原文、录音、姓名、学校、联系方式**。

---

## 1. 指标体系与口径

### 1.1 数据来源

| 来源 | 位置 | 用途 |
| --- | --- | --- |
| 导出 JSON | `#stats` → 「导出学习数据 JSON」，文件名 `alter-<试用编号>-<导出日期>.json` | 逐人指标的唯一原始依据 |
| 隐藏数据页 `#stats` | 连点左上角 ALTER 5 次，或直接打开 `#stats` | 组织者现场核对漏斗、计数、活跃天数 |
| 家长周报 `#report` | `#stats` → 「打开家长周报」 | 家长自看，不作为汇总口径 |

导出 JSON（`schema: "alter-trial-v1"`）结构：

```
{
  "app": "ALTER",
  "schema": "alter-trial-v1",
  "version": 1,
  "trialId": "T01",          // 试用编号；未设置时为 null
  "exportedAt": "2026-11-19T...",
  "firstDay": "2026-11-05",  // 本机第一次记录事件的日期
  "lastDay": "2026-11-18",
  "count": 214,
  "events": [
    { "name": "beat_complete", "day": "2026-11-06", "t": 1762..., "props": { "sceneId": "s1-a1", "beatId": "s1-a1-b2", "grade": "native", "firstPass": true } }
  ]
}
```

事件只含：`app_open`、`persona_pick`、`scene_start`、`beat_complete`、`scene_complete`、`speech_use`、`card_generated`、`card_saved`、`day2_return`、`review_clear`。`props` 只允许数字/布尔/短字符串，`text / line / transcript / heard / solution / intent / situation` 等字段在写入前会被丢弃。

### 1.2 指标定义与算法

| 指标 | 口径定义 | 从哪个字段算 | `#stats` 对应展示 | `#report` 对应展示 |
| --- | --- | --- | --- | --- |
| **D1 回访率** | 首日后第 2 天有打开或学习事件的用户 ÷ 进入试用且已过第 2 天的用户 | `firstDay` + `events[].day/name`（`app_open` 或 `beat_complete/review_clear`） | 不直接展示；「每日活跃」柱状图可人工看 | 不展示 |
| **7 日内学习天数** | 从 `firstDay` 起 7 个自然日内，有 `beat_complete` 或 `review_clear` 的不同日期数 | `events[].day` + `name` | 「每日活跃」最近 14 天（不是首 7 天，需导出算） | `metrics.studyDays` 是“最近 7 天”，不是“首 7 天” |
| **每集完成率** | `scene_complete` 的去重 `sceneId` 数 ÷ `scene_start` 的去重 `sceneId` 数 | `events[]` 的 `props.sceneId` | 漏斗「开始一集 / 完成整集」两个计数 | `metrics.scenes`（完成集数） |
| **开口说使用比例** | `speech_use` 去重 `beatId` 数 ÷ `beat_complete` 去重 `beatId` 数 | 同上 | 「开口说比例」卡片（0–100%） | `metrics.speech`（次数）与 `metrics.beats` |
| **分享卡生成率** | `card_generated` 去重 `sceneId` ÷ `scene_complete` 去重 `sceneId` | `events[]` 的 `sceneId` | 漏斗「生成分享卡」 | 不展示 |
| **分享卡保存率** | `card_saved` 去重 `sceneId` ÷ `card_generated` 去重 `sceneId` | 同上 | 「分享卡保存率」卡片（保存÷完成） | 不展示 |
| **复习使用率** | 至少完成 1 句 `review_clear` 的用户数 ÷ 至少完成 1 集的用户数（近似值，见 1.4） | `review_clear`、`scene_complete` | 「复习完成」计数 | `metrics.reviews` |
| **卡在哪一集流失** | 每人按场景顺序（`s1-a1 … s3-a5`）取最后一个 `scene_start` 的场景；若该场景没有 `scene_complete`，记为“卡在该集” | `scene_start` / `scene_complete` 的 `sceneId` | 不展示 | 不展示 |

### 1.3 每人一行指标（合并脚本输出）

`d1`、`studyDays7`、`scenesStarted`、`scenesCompleted`、`completionRate`、`speechUses`、`beats`、`speechRatio`、`cardsGenerated`、`cardsSaved`、`shareGenRate`、`shareSaveRate`、`reviews`、`lastScene`、`stuckScene`、`active`。

### 1.4 口径限制（写进结论里）

- **500 条上限**：导出最多 500 条事件；两周内重度用户可能接近上限。`firstDay` 单独保存，不受裁剪影响；但极端情况下首日之后的早期事件可能被裁掉，需在汇总时标注 `count === 500`。
- **复习使用率是近似值**：导出中没有“到期句数”事件，分母用“完成 ≥1 集的用户”，只用于判断复习功能是否被真正使用，不当作复习完成率。
- **D1 的分母**：只统计首日后已完整经过第 2 天的用户；试用第 13–14 天才加入的用户不参与 D1，避免低估。
- **设备口径**：一人一设备；若同一人换设备/清缓存，会产生两份数据，用 `trialId` + 家长确认合并或标记为两份。
- **家长周报不是汇总源**：周报的 7 天窗口随打开日期滚动，不是“试用首 7 天”。

## 2. 回收流程（无后端）

### 2.1 试用前：发编号与链接

1. 按名册分配编号：`T01` … `T100`（只用编号，不把姓名写进 App）。
2. 每位家长拿到专属链接：`https://elizabeth819.github.io/alter-english/?trial=T01`。
3. 家长第一次用该链接打开后，编号会存在本机；之后从桌面图标打开也会带上。编号只显示在隐藏数据页，不进入孩子的正常界面。
4. 组织者另存一份「编号 ↔ 家长微信」名册，**与数据文件分开存放**，试用结束即删除。

### 2.2 试用中：家长怎么看

- 查看：连点左上角 ALTER 标志 5 次，或直接打开 `#stats`；可看漏斗、完成幕数、开口说比例、分享卡保存率、最近 14 天活跃。
- 周报：`#stats` →「打开家长周报」，可打印/存 PDF。
- 删除：同一页底部「清除本机所有进度与学习数据」，或在 `#stats` 页的「清除…」入口；删除后不可恢复。
- 孩子端不出现“试用”“实验”字样，避免影响自然使用。

### 2.3 试用结束：家长导出

1. 打开 `#stats`，点「导出学习数据 JSON」。
2. 文件名自动为 `alter-<编号>-<导出日期>.json`，例如 `alter-T01-2026-11-19.json`。
3. 直接把文件发到家长群/组织者，**不需要改名**；如需重命名，保留 `T01` 前缀即可。
4. 文件只含本机统计事件，不含对话原文、录音、姓名、学校。

### 2.4 组织者归档与校验

目录建议：

```
trial/
  raw/                 # 原样收上来的 JSON，不改名、不编辑
    alter-T01-2026-11-19.json
    alter-T02-2026-11-20.json
  out/                 # 合并脚本输出
    users.csv
    summary.json
```

逐份校验（合并脚本会自动做，并给出告警）：

| 校验项 | 规则 |
| --- | --- |
| 文件类型 | `app === "ALTER"` 且 `schema === "alter-trial-v1"` |
| 编号一致 | `trialId` 与文件名/名册一致；为空则告警并按文件名推断 |
| 条数一致 | `count === events.length` |
| 时间范围 | `firstDay`、`lastDay` 落在试用窗口内（允许 1 天时区误差） |
| 版本 | `version === 1`；未知版本只告警不丢弃 |
| 重复导出 | 同一 `trialId` 多份时，取 `exportedAt` 最新的一份，并提示前后条数差 |
| 隐私字段 | 事件 `props` 出现 `text/line/transcript/heard/solution/intent/situation/prompt/note` 任一键即告警并剔除该键 |
| 事件上限 | `count === 500` 标注“可能被裁剪”，结论里降权 |

### 2.5 本次最小改动（已上线）

| 改动 | 位置 | 说明 |
| --- | --- | --- |
| 试用编号 | `app.js` 读取 `?trial=`，存 `alter.trial.v1`，`#stats` 显示编号 | 只存编号，不含个人信息 |
| 导出文件名 | `alter-<编号或 local>-<日期>.json` | 收上来即可按人归档 |
| 导出字段 | `schema: "alter-trial-v1"`、`trialId`、`firstDay`、`lastDay` | 合并脚本据此校验与算 D1 |
| 首次日期 | `analytics.js` 在首条事件时记录 `firstDay`，裁剪不丢 | 500 条上限下仍能算 D1 |

不做的事：不加后端、不加账号、不上传、不加“试用模式”界面开关（用链接参数即可，孩子端无感）。

## 3. 归档与合并脚本

脚本：`alter/tools/trial-merge.mjs`（零依赖、只读本地 JSON、不联网）。

### 3.1 运行

```bash
# 标准 Node
node tools/trial-merge.mjs <rawDir> --out <outDir>

# 本机没有 node 时（Electron 以 Node 方式运行）
ELECTRON_RUN_AS_NODE=1 "<Trae CN.exe>" tools/trial-merge.mjs <rawDir> --out <outDir>

# 只统计某段时间（可选）
node tools/trial-merge.mjs ../trial/raw --out ../trial/out --from 2026-11-05 --to 2026-11-18
```

示例：

```bash
node tools/trial-merge.mjs ../trial/raw --out ../trial/out
# 已读取 87 个文件，合并 84 人
# D1 回访：61/80 = 76.3%
# 首 7 日学习天数（均值）：4.2（可评估 76 人）
# 每集完成率：71.4%（312/437）
# 开口说比例：38.6% · 使用过开口的用户 64.3%
# 分享卡：生成率 52.1% · 保存率 46.8%
# 复习使用率：41.7%
# 卡点：s1-a3×4、s1-a5×3、s2-a1×2
```

### 3.2 输出

`out/users.csv`（UTF-8 BOM，Excel 可直接打开，一人一行）：

| 列 | 含义 |
| --- | --- |
| `trialId` | 试用编号；缺失时为空，用 `file` 兜底 |
| `firstDay` / `lastDay` / `daysObserved` | 首末记录日与跨度 |
| `openDays` | 有打开记录的天数 |
| `d1Eligible` / `d1` | 是否已过第 2 天 / 第 2 天是否回访 |
| `studyDays7` | 首 7 日内有学习的天数 |
| `scenesStarted` / `scenesCompleted` | 去重场景数 |
| `beats` / `speechUses` / `speechRatio` | 完成幕数、开口幕数、开口比例 |
| `cardsGenerated` / `cardsSaved` | 去重分享卡生成/保存数 |
| `reviews` | 复习完成句数 |
| `lastScene` / `stuckScene` | 最后触达 / 卡住未完成的场景 |
| `active` / `capped` | 是否有学习行为 / 是否触顶 500 条 |
| `exportedAt` / `file` | 导出时间与原文件名（可追溯） |

`out/summary.json`：总体汇总 + `dropoff`（按 `s1-a1 … s3-a5` 排序的逐集开始/完成/卡住人数）+ `warnings`。

### 3.3 校验与规则

- 坏 JSON、非 ALTER 文件：跳过并告警，不中断。
- 同一 `trialId` 多份：保留 `exportedAt` 最新的一份。
- 隐私字段：`text/line/lineCn/transcript/heard/solution/note/intent/situation/prompt` 一律剔除并告警。
- `count !== events.length`、未知 `schema/version`、`count === 500`：告警但不丢弃（触顶用户在结论中降权）。
- 文件名无编号：按 `alter-<编号>-<日期>.json` 推断；payload 无编号则用文件名兜底。
- 逐集卡点只统计“最后一次触达且未完成”的场景，重复进入同一集不会重复计数。

脚本自检样例在 `_qa/trial-fixtures/`（5 人、含重复导出、坏文件、隐私字段、缺编号），可复跑：

```bash
node tools/trial-merge.mjs ../_qa/trial-fixtures/raw --out ../_qa/trial-fixtures/out
```

## 4. 判读标准（试用前先定好，避免事后改口）

### 4.1 决策前置：数据够不够

只有同时满足以下条件，才进入放量/收紧/放弃的判断：

- 有效用户 ≥ 40（有 `firstDay`、至少 1 条学习事件、编号可对应）；
- 导出回收率 ≥ 70%（收到导出的人数 ÷ 实际开始试用的人数）；
- 其中 ≥ 30 人已完整经过首 7 天（`daysObserved ≥ 7`）；
- 触顶 500 条的用户 ≤ 20%；
- 没有出现“同一编号多份且差异巨大”“系统时间明显错误”等无法解释的数据问题。

不满足任一条 → **数据不足，不下结论**；延长回收或补招一小批（30 人）重跑，而不是降低阈值。

### 4.2 指标门槛

| 指标 | 放量 | 观察 / 先收紧 | 放弃信号 |
| --- | --- | --- | --- |
| D1 回访率 | ≥ 60% | 40%–60% | < 40% |
| 首 7 日学习天数（均值） | ≥ 3.5 天 | 2–3.5 天 | < 2 天 |
| 每集完成率（开始→完成） | ≥ 70% | 50%–70% | < 50% |
| 开口说比例（开口幕 ÷ 完成幕） | ≥ 30% | 15%–30% | < 15% |
| 分享卡生成率（生成 ÷ 完成集） | ≥ 40% | 20%–40% | < 20% |
| 分享卡保存率（保存 ÷ 生成） | ≥ 40% | 20%–40% | < 20% |
| 复习使用率（近似） | ≥ 40% | 20%–40% | < 20% |

### 4.3 结论规则

1. **放弃**：D1 < 40% 且首 7 日学习天数 < 2（留存双杀），或每集完成率 < 50%（连第一集都过不去），或“开口 < 15% 且分享保存 < 20%”（核心体验没被使用）。任一“放弃信号”出现，先复盘再决定是否重做，不直接放量。
2. **放量**：D1、学习天数、完成率、开口比例 4 项全部达到“放量”，分享卡与复习不作为硬门槛（但需记录）；且无阻断性 bug、无集中卡点。
3. **收紧**：未达放量、也未触发放弃 → 只针对最低的 1–2 项做改动，2–3 周后用 30–50 人复测；不要同时改多个变量。
4. **卡点优先**：若某一集 `stuckHere` 占该集开始人数的 ≥ 30%，即使总指标达标也先修这一集，再谈放量。

### 4.4 样本量 50–100 的置信度

以 95% 置信区间、比例指标近似 `±1.96×√(p(1−p)/n)`：

| 样本量 | p=60% 时约 | p=40% 时约 | 解读 |
| --- | --- | --- | --- |
| 50 | ±13.6pp | ±13.6pp | 只能看大方向，60% 与 50% 分不清 |
| 80 | ±10.7pp | ±10.7pp | 可用于“明显好/明显差”的判断 |
| 100 | ±9.6pp | ±9.6pp | 仍不足以判断 5pp 级别差异 |

因此：

- 阈值附近 ±5pp 视为**灰区**，不要用“刚好 59%”得出“没达标”的结论；
- 学习天数是均值，n=80 时标准误约 ±0.2–0.3 天，报告均值时同时给中位数与分布（`summary.json` 已有分布）；
- 不做 < 20 人的子组对比（如按年级、性别、设备）；
- 两周数据只能回答“是否值得继续投入”，不能回答长期留存、付费意愿。

### 4.5 属于“数据不足以下结论”的情况

- 回收率 < 70%，或缺编号/编号重复无法对应；
- 有效用户 < 40，或完整 7 天观测 < 30 人；
- 大量用户在第 1–2 天集中开始（如统一开营），导致 D1 窗口未成熟；
- 组织者每天提醒/代操作，无法区分自然使用；
- 同一家庭多设备重复导出且无法确认是否同一人；
- 事件触顶比例过高，首日行为被裁剪；
- 指标之间互相矛盾（如完成率很高但学习天数极低），先查数据再判断。

### 5.1 第 7 天中途检查（建议做，但只查不改）

目的：确认数据能收回来、发现阻断性问题；**不用于提前下结论**。

- 抽样 10–15 位家长，按正常流程导出一次（不额外辅导）；
- 检查：编号正确、文件名正确、`schema` 正确、无隐私字段、事件数是否接近 500；
- 看一次 `summary.json` 的卡点分布，只记录，不改产品；
- 只有当出现“无法打开/无法导出/语音完全不可用”这类阻断问题时才发版修复，并在结论中标注“中途修复过”；
- 不因 D7 指标好看或难看调整阈值。

## 6. 隐私边界与家长权利

### 6.1 收什么、不收什么

| 收集（统计） | 不收集 |
| --- | --- |
| 事件名（打开/开始一集/完成一幕/开口/分享/复习） | 对话原文、词块内容、识别文本 |
| 本地日期、时间戳 | 录音、音频 |
| 场景/回合 id、判定等级、是否首次通过 | 姓名、学校、班级、电话、微信 |
| 计数（幕数、开口次数、分享次数） | 位置、设备标识、广告标识 |

- 数据只存在各自设备的 `localStorage`，不上传、不经过服务器、不接第三方统计。
- 导出文件只有编号（如 `T01`），没有身份信息；编号与家长的对应关系只在组织者本地名册里，且分开存放。

### 6.2 家长如何查看、导出、删除

- 查看：连点左上角 ALTER 5 次，或打开 `#stats`；可看漏斗、计数、开口比例、分享保存率、最近 14 天活跃。
- 导出：同页「导出学习数据 JSON」，得到 `alter-T01-日期.json`。
- 删除：同页「清除本机所有进度与学习数据」；确认后进度、句子本、统计事件全部清空，不可恢复。若需连试用编号一起清除，可在浏览器设置里清除该站点数据。
- 孩子端没有任何“上传/同步/账号”入口。

### 6.3 组织者义务

- 试用前取得家长同意，同意记录与数据文件分开保存；
- 不把原始 JSON 发到公开群；汇总只发聚合指标；
- 试用结论产出后 7 天内删除名册与 `trial/raw`，只保留 `summary.json` 与结论；
- 任何人索要原始数据，先核对编号与家长身份，再提供其本人的那一份。
